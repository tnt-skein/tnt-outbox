# tnt-outbox

Ящик исходящих (outbox) для Tarantool: событие пишется строкой спейса
в той же транзакции, что и данные, а уходит отдельным вывозом. Откат
уносит обоих, фиксация оставляет обоих, и «сохранили и отправили»
перестаёт терять события при обрыве между двумя действиями.

```lua
local outbox = require('tnt.outbox')

-- Отправитель — любая таблица с send(name, body, opts) → id | nil, err.
outbox.configure({ senders = { ['order.paid'] = webhook } })
outbox.start()                                   -- при подъёме узла: спейсы заведены, вывоз пошёл

box.atomic(function()
    orders:insert({ 11, 'оплачен' })
    outbox.write('order.paid', { order = 11 })   -- событие — строкой той же транзакции
end)
```

Зависимости: `tnt-message` (общая часть договора очереди: конверт, проверка
настроек и тела, приговор обработчику, область обработчика и крюки), `tnt-must` (проверки
аргументов), `tnt-clock` (время записи, отметки и планировщика), `tnt-id`
(опознаватель ULID), `tnt-log` (журнал), `tnt-loop` (такты
вывоза и уборки отметок), `tnt-retry` (отступ после отказа), `tnt-metrics`
(ряды ящика) и `tnt-external` (подмена транзакции, спейсов и часов
в проверках).

## Зачем

«Сохранили и отправили» двумя действиями теряет событие при обрыве между
ними, и потеря тихая. Отправить прямо в транзакции тоже нельзя:
отправитель ходит по сети, уступка рвёт транзакцию, а ушедшее сообщение
откат не вернёт. Пакет делает шесть вещей:

- **Запись — вставка в транзакции вызывающего**: откат уносит событие
  вместе с данными, а вне транзакции запись переживает перезапуск.
- **Отправляется только зафиксированное**: отметку ставит
  `box.on_commit` записи, лежавшее до запуска открывает барьер
  поколения, и строку транзакции, ждущей кворума, вывоз не отправит.
- **Порядок держится ключом** — последовательностью спейса; строка,
  на которой отправитель отказал, ждёт, а не пропускается.
- **Отказы разделены**: повторяемый оставляет строку на месте
  и откладывает вывоз растущим отступом, неповторяемый уводит её
  в `outbox_dead`, а `kick` возвращает её на отправку.
- **Опознаватель и заголовки ставит запись**: ULID и заголовки
  контекста ложатся в строку, и повторная отправка несёт те же.
- **Настройки проверяются при записи**, а не на вывозе через час.

Гарантия — хотя бы раз: повтор несёт тот же опознаватель, и отсекает его
получатель — отметкой `tnt.outbox.inbox` в транзакции обработчика.

## Установка

```sh
tt rocks install tnt-outbox --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-outbox.git
cd tnt-outbox && tt rocks make
```

## Как пользоваться

| Вызов | Что делает |
|---|---|
| `outbox.configure(opts)` | отправители по именам назначений, `interval`, `batch`, `backoff`; негодное — исключение |
| `outbox.start()` | первый проход в файбере вызывающего — спейсы заведены, — затем такт вывоза |
| `outbox.write(name, body, opts)` | кладёт событие в ящик и отдаёт его ULID; настройки — `headers`, `key`, `delay`, `ttl`, `priority`, `id`, `timeout` |
| `outbox.flush()` | один проход вывоза прямо сейчас; отчёт `{ sent, dead, more, skipped, err, stalled }` |
| `outbox.stop()` | останавливает такт; строки остаются |
| `outbox.dead(limit)` | зарытые строки с причиной; по умолчанию сто |
| `outbox.kick(count)` | возвращает до `count` зарытых в хвост ящика с тем же опознавателем; по умолчанию одну, не больше тысячи |
| `outbox.status()` | такт, настройки, глубина, возраст головы, счётчики |
| `outbox.reset()` | забывает настройки, счёт и отметки; строки в спейсах остаются |

Отправитель — таблица с `send(name, body, opts) → id | nil, err`
и признаками `features`: `false` у `key`, `delay`, `ttl` или `priority`
значит «не умею», и запись с такой настройкой отвергается сразу.
`err.retriable == false` уводит строку в зарытые, остальные отказы —
повторяемые.

```lua
outbox.write('order.paid', { order = 11 }, { key = 'o-11' })
--> error: настройки записи: «key» — отправитель не умеет
```

Спейсы `outbox`, `outbox_dead` и `outbox_barrier` заводит сам пакет
первым проходом вывоза: заведение — DDL, и в чужой транзакции оно
порвало бы её. Главный ряд тревоги — возраст головы: `oldest_seconds`
в `status()` и ряд метрик `outbox_oldest_seconds`; вывоз, стоящий
на отказе отправителя, иначе не виден. Рядом — `outbox_depth` (ждёт
вывоза и зарыто), `outbox_sent_total` и `outbox_dead_total`
по назначению.

### Отметки получателя

Повтор доставки — у любой долговечной очереди, и отсекает его получатель.
`tnt.outbox.inbox` ставит отметку «получатель, `id`» в транзакции
обработчика: фиксация оставляет и запись, и отметку, откат снимает обе.

```lua
local inbox = require('tnt.outbox.inbox')

inbox.start()                                    -- при подъёме узла: спейс заведён, уборка пошла

box.atomic(function()
    if inbox.claim('receipts', message) then     -- false — повтор: делать нечего
        box.space.receipts:insert({ message.id, message.body.order })
    end
end)
```

| Вызов | Что делает |
|---|---|
| `inbox.claim(receiver, message)` | отметка в транзакции вызывающего: `true` — впервые, `false` — повтор; вне транзакции — исключение |
| `inbox.configure(opts)` | срок хранения `retention` (неделя), такт `interval` (60 с), кусок `batch` (1000) |
| `inbox.start()` | первый проход уборки — спейс `outbox_inbox` заведён, — затем такт |
| `inbox.sweep()` | один проход уборки: стирает отметки старше срока, на реплике молчит |
| `inbox.stop()`, `inbox.status()`, `inbox.reset()` | такт, сводка с возрастом старшей отметки, сброс |

Срок хранения — не меньше самого длинного окна повтора: повтор после
уборки своей отметки обработается второй раз.

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov и зависимости пакета в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (87 проверок,
464 мутанта в семи модулях). Проход вывоза проверяется на двойнике
спейсов, отметки фиксации — на двойнике транзакции; три группы поднимают
узел Tarantool: настоящие спейсы, триггеры фиксации, последовательность,
синхронная транзакция, которая ждёт кворума и откатывается, и отметки
получателя — откат вместе с записью обработчика и уборка по сроку.
